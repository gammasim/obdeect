Ray tracing: optical-model inputs are used or rejected, never dropped. The C++ loader checks the `sha256` entry of text and validates the `sampling`, `provenance` and `notes` blocks (a negative disk radius was accepted). The compiler rejects a single zenith term of the focus offset, a method-0 transmission amplitude, a dual-mirror outer power other than 0 or 1, a negative secondary shadow offset, an overshooting reflectivity and a zero dish length, and it requires `mirror_class`, `camera_body_shape`; `propagation_group_index` is passed explicitly: `obdeect ray-tracing compile` needs `--propagation-group-index` for a telescope without a site (such as `MSTx-FlashCam`; 1.0 gives the model it had before), and `OpticalModel.from_records` without it warns (DeprecationWarning) and keeps the former 1.0. Mirror-list rows take the documented six columns and an optional panel id. Star photons start above the asphere rims and obscurer walls as well: the start height only moves where the old heights were too low, so no production telescope changes (all 162 compiled hashes are unchanged). Fixed: ring segment ids, empty response files (`IndexError`), missing structure coordinates (`KeyError`), the 2-D RPOL scheme being overwritten, and a zero RPOL scale being replaced by one.
